TLS Hardware Offload Two-Node Test

Usage:
  /home/validation1/testrunner/repository/ksft/drivers/net/hw/tls_hw_offload server [OPTIONS]
  /home/validation1/testrunner/repository/ksft/drivers/net/hw/tls_hw_offload client -s <ip> [OPTIONS]

Options:
  -s <ip>       Server IPv4 address (client, required)
  -p <port>     Server port (default: 4433)
  -b <size>     Send buffer size in bytes (default: 16384)
  -r <max>      Use random send buffer sizes (1..<max>)
  -v <version>  TLS version: 1.2 or 1.3 (default: 1.3)
  -c <cipher>   Cipher: 128 or 256 (default: 128)
  -n <N>        Number of send/echo iterations (default: 100)
  -k <N>        Perform N rekeys (client only, TLS 1.3; N < iterations)
  -B            Burst mode: client sends continuously without echo;
                server drains and handles KeyUpdate without responding.
  -Z            Set TLS_RX_EXPECT_NO_PAD on the server: TLS 1.3
                opt-in to the zero-copy RX fast path. Not needed
                for TLS 1.2 (always eligible). Server only.
  -h            Show this help message

Example:
  Node A: /home/validation1/testrunner/repository/ksft/drivers/net/hw/tls_hw_offload server
  Node B: /home/validation1/testrunner/repository/ksft/drivers/net/hw/tls_hw_offload client -s 192.168.20.2

Rekey Example (3 rekeys, TLS 1.3 only):
  Node A: /home/validation1/testrunner/repository/ksft/drivers/net/hw/tls_hw_offload server
  Node B: /home/validation1/testrunner/repository/ksft/drivers/net/hw/tls_hw_offload client -s 192.168.20.2 -k 3

Burst Mode Example (client stresses TX rekey under load):
  Node A: /home/validation1/testrunner/repository/ksft/drivers/net/hw/tls_hw_offload server -B
  Node B: /home/validation1/testrunner/repository/ksft/drivers/net/hw/tls_hw_offload client -s 192.168.20.2 -B -k 3
